1f:T3c95,<h2 id="why-signals-are-everywhere">Why signals are everywhere</h2>
<p>Solid, Preact Signals, Angular, Vue, Svelte 5 runes and the TC39 Signals proposal all share one idea: <strong>track exactly which computations read which values, and re-run only those when a value changes.</strong> Instead of re-rendering a component tree and diffing, a signal-based UI updates the one text node that depends on the changed value.</p>
<p>The best way to understand it is to build one. We'll write <code>signal</code>, <code>computed</code> and <code>effect</code> in plain JavaScript.</p>
<h2 id="step-1-a-signal-is-a-value-with-subscribers">Step 1: a signal is a value with subscribers</h2>
<pre><code class="hljs language-js"><span class="hljs-keyword">let</span> currentObserver = <span class="hljs-literal">null</span>;

<span class="hljs-keyword">export</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">signal</span>(<span class="hljs-params">initial</span>) {
  <span class="hljs-keyword">let</span> value = initial;
  <span class="hljs-keyword">const</span> subscribers = <span class="hljs-keyword">new</span> <span class="hljs-title class_">Set</span>();

  <span class="hljs-keyword">const</span> <span class="hljs-title function_">read</span> = (<span class="hljs-params"></span>) => {
    <span class="hljs-comment">// Auto-tracking: whoever is running right now depends on us</span>
    <span class="hljs-keyword">if</span> (currentObserver) {
      subscribers.<span class="hljs-title function_">add</span>(currentObserver);
      currentObserver.<span class="hljs-property">dependencies</span>.<span class="hljs-title function_">add</span>(subscribers);
    }
    <span class="hljs-keyword">return</span> value;
  };

  <span class="hljs-keyword">const</span> <span class="hljs-title function_">write</span> = (<span class="hljs-params">next</span>) => {
    <span class="hljs-keyword">if</span> (<span class="hljs-title class_">Object</span>.<span class="hljs-title function_">is</span>(next, value)) <span class="hljs-keyword">return</span>;
    value = next;
    <span class="hljs-comment">// Copy first: running effects may modify the set</span>
    <span class="hljs-keyword">for</span> (<span class="hljs-keyword">const</span> sub <span class="hljs-keyword">of</span> [...subscribers]) sub.<span class="hljs-title function_">schedule</span>();
  };

  <span class="hljs-keyword">return</span> [read, write];
}
</code></pre>
<p>The key trick is <code>currentObserver</code>: a global pointer to "the computation currently executing". Any signal read while it's set records a dependency. This is <strong>automatic dependency tracking</strong> — no dependency arrays.</p>
<h2 id="step-2-effects">Step 2: effects</h2>
<p>An effect runs a function, tracking everything it reads. When any of those change, it re-runs.</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">function</span> <span class="hljs-title function_">cleanup</span>(<span class="hljs-params">observer</span>) {
  <span class="hljs-keyword">for</span> (<span class="hljs-keyword">const</span> dep <span class="hljs-keyword">of</span> observer.<span class="hljs-property">dependencies</span>) dep.<span class="hljs-title function_">delete</span>(observer);
  observer.<span class="hljs-property">dependencies</span>.<span class="hljs-title function_">clear</span>();
}

<span class="hljs-keyword">export</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">effect</span>(<span class="hljs-params">fn</span>) {
  <span class="hljs-keyword">const</span> observer = {
    <span class="hljs-attr">dependencies</span>: <span class="hljs-keyword">new</span> <span class="hljs-title class_">Set</span>(),
    <span class="hljs-title function_">schedule</span>(<span class="hljs-params"></span>) {
      <span class="hljs-title function_">run</span>();
    },
  };

  <span class="hljs-keyword">function</span> <span class="hljs-title function_">run</span>(<span class="hljs-params"></span>) {
    <span class="hljs-title function_">cleanup</span>(observer); <span class="hljs-comment">// dependencies can change between runs</span>
    <span class="hljs-keyword">const</span> prev = currentObserver;
    currentObserver = observer;
    <span class="hljs-keyword">try</span> {
      <span class="hljs-title function_">fn</span>();
    } <span class="hljs-keyword">finally</span> {
      currentObserver = prev;
    }
  }

  <span class="hljs-title function_">run</span>();
  <span class="hljs-keyword">return</span> <span class="hljs-function">() =></span> <span class="hljs-title function_">cleanup</span>(observer); <span class="hljs-comment">// dispose</span>
}
</code></pre>
<p>Why <code>cleanup</code> before every run? Consider conditional reads:</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">const</span> [showName, setShowName] = <span class="hljs-title function_">signal</span>(<span class="hljs-literal">true</span>);
<span class="hljs-keyword">const</span> [name, setName] = <span class="hljs-title function_">signal</span>(<span class="hljs-string">"Ada"</span>);

<span class="hljs-title function_">effect</span>(<span class="hljs-function">() =></span> {
  <span class="hljs-variable language_">console</span>.<span class="hljs-title function_">log</span>(<span class="hljs-title function_">showName</span>() ? <span class="hljs-title function_">name</span>() : <span class="hljs-string">"hidden"</span>);
});

<span class="hljs-title function_">setShowName</span>(<span class="hljs-literal">false</span>); <span class="hljs-comment">// logs "hidden"</span>
<span class="hljs-title function_">setName</span>(<span class="hljs-string">"Grace"</span>);   <span class="hljs-comment">// should NOT re-run — name is no longer read</span>
</code></pre>
<p>Re-collecting dependencies on each run means the effect stops listening to <code>name</code> once the branch that read it is gone. This <strong>dynamic dependency tracking</strong> is something React's static dependency arrays can't express.</p>
<h2 id="step-3-computed-values">Step 3: computed values</h2>
<p>A <code>computed</code> is both an observer (it reads signals) and a source (others read it). It should be <strong>lazy</strong> and <strong>cached</strong>: only recompute when read <em>and</em> stale.</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">export</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">computed</span>(<span class="hljs-params">fn</span>) {
  <span class="hljs-keyword">let</span> value;
  <span class="hljs-keyword">let</span> dirty = <span class="hljs-literal">true</span>;
  <span class="hljs-keyword">const</span> subscribers = <span class="hljs-keyword">new</span> <span class="hljs-title class_">Set</span>();

  <span class="hljs-keyword">const</span> observer = {
    <span class="hljs-attr">dependencies</span>: <span class="hljs-keyword">new</span> <span class="hljs-title class_">Set</span>(),
    <span class="hljs-title function_">schedule</span>(<span class="hljs-params"></span>) {
      <span class="hljs-keyword">if</span> (dirty) <span class="hljs-keyword">return</span>;
      dirty = <span class="hljs-literal">true</span>;
      <span class="hljs-comment">// Propagate staleness, don't recompute yet</span>
      <span class="hljs-keyword">for</span> (<span class="hljs-keyword">const</span> sub <span class="hljs-keyword">of</span> [...subscribers]) sub.<span class="hljs-title function_">schedule</span>();
    },
  };

  <span class="hljs-keyword">return</span> <span class="hljs-function">() =></span> {
    <span class="hljs-keyword">if</span> (currentObserver) {

</code></pre>
<pre><code class="hljs language-js"><span class="hljs-keyword">const</span> [first, setFirst] = <span class="hljs-title function_">signal</span>(<span class="hljs-string">"Ada"</span>);

<h2 id="step-4-batching-and-the-glitch-problem">Step 4: batching and the glitch problem</h2>
<p>Our naive implementation has a flaw. Look at this "diamond" graph:</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">const</span> [a, setA] = <span class="hljs-title function_">signal</span>(<span class="hljs-number">1</span>);
<span class="hljs-keyword">const</span> b = <span class="hljs-title function_">computed</span>(<span class="hljs-function">() =></span> <span class="hljs-title function_">a</span>() * <span class="hljs-number">2</span>);
<span class="hljs-keyword">const</span> c = <span class="hljs-title function_">computed</span>(<span class="hljs-function">() =></span> <span class="hljs-title function_">a</span>() + <span class="hljs-number">1</span>);

<span class="hljs-title function_">effect</span>(<span class="hljs-function">() =></span> <span class="hljs-variable language_">console</span>.<span class="hljs-title function_">log</span>(<span class="hljs-title function_">b</span>(), <span class="hljs-title function_">c</span>()));
<span class="hljs-title function_">setA</span>(<span class="hljs-number">2</span>);
</code></pre>
<p>The effect depends on <code>a</code> twice (through <code>b</code> and <code>c</code>). With eager scheduling, it can run once after <code>b</code> is marked dirty and again after <code>c</code> — the first run might even see an inconsistent mix of old and new values. That intermediate state is called a <strong>glitch</strong>.</p>
<p>The fix used by real libraries is two-phase propagation: first <strong>mark</strong> everything downstream as stale, then <strong>run</strong> effects once, after the write completes. A simple version uses a queue and a batch depth:</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">let</span> batchDepth = <span class="hljs-number">0</span>;
<span class="hljs-keyword">const</span> pendingEffects = <span class="hljs-keyword">new</span> <span class="hljs-title class_">Set</span>();

<span class="hljs-keyword">export</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">batch</span>(<span class="hljs-params">fn</span>) {
  batchDepth++;
  <span class="hljs-keyword">try</span> {
    <span class="hljs-title function_">fn</span>();
  } <span class="hljs-keyword">finally</span> {
    batchDepth--;
    <span class="hljs-keyword">if</span> (batchDepth === <span class="hljs-number">0</span>) <span class="hljs-title function_">flush</span>();
  }
}

<span class="hljs-keyword">function</span> <span class="hljs-title function_">flush</span>(<span class="hljs-params"></span>) {
  <span class="hljs-keyword">for</span> (<span class="hljs-keyword">const</span> run <span class="hljs-keyword">of</span> [...pendingEffects]) {
    pendingEffects.<span class="hljs-title function_">delete</span>(run);
    <span class="hljs-title function_">run</span>();
  }
}
</code></pre>
<p>Then change the effect's <code>schedule</code> to enqueue instead of running immediately, and have <code>write</code> wrap its notifications in <code>batch</code>:</p>
<pre><code class="hljs language-js"><span class="hljs-title function_">schedule</span>(<span class="hljs-params"></span>) {
  pendingEffects.<span class="hljs-title function_">add</span>(run);
},

<span class="hljs-comment">// inside signal's write():</span>
<span class="hljs-title function_">batch</span>(<span class="hljs-function">() =></span> {
  <span class="hljs-keyword">for</span> (<span class="hljs-keyword">const</span> sub <span class="hljs-keyword">of</span> [...subscribers]) sub.<span class="hljs-title function_">schedule</span>();
});
</code></pre>
<p>Now the diamond logs <code>4 3</code> exactly once. Because <code>computed</code> values are lazy and only recompute when read, the effect always sees a consistent snapshot. Production libraries go further, tracking per-node versions or colours ("clean / check / dirty") so that a computed whose inputs changed but whose <em>output</em> didn't stops propagation early.</p>

<h2 id="trade-offs-worth-knowing">Trade-offs worth knowing</h2>
<ul>
<li><strong>Memory:</strong> every dependency edge is a <code>Set</code> entry. Large graphs need cleanup on disposal or they leak.</li>
<li><strong>Debuggability:</strong> implicit tracking is convenient but can hide why something re-ran. Good devtools matter.</li>
<li><strong>Equality:</strong> <code>Object.is</code> means mutating an object in place won't notify. Treat signal values as immutable, or use a custom equality function.</li>
</ul>

<p>Signals come down to a global "current observer" pointer, sets of subscribers, lazy cached derivations and a scheduler that avoids glitches.
