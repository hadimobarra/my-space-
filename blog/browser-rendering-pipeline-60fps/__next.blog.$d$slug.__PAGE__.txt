3:T3656,<h2 id="the-pixel-pipeline">The pixel pipeline</h2>
<p>Every frame the browser produces goes through up to five stages:</p>
<pre><code class="hljs language-text">JavaScript → Style → Layout → Paint → Composite
</code></pre>
<ol>
<li><strong>JavaScript</strong> — your code (or CSS animations/transitions) changes something.</li>
<li><strong>Style</strong> — the browser works out which CSS rules apply to which elements and computes final styles.</li>
<li><strong>Layout</strong> — it calculates the geometry of every affected box: size and position.</li>
<li><strong>Paint</strong> — it records drawing commands (text, colours, borders, shadows, images) for each layer.</li>
<li><strong>Composite</strong> — layers are rasterised (often on the GPU) and assembled into the final image.</li>
</ol>
<p>At 60Hz you have <strong>16.7ms per frame</strong> for all of this, and in practice closer to 10ms of budget for your own work. At 120Hz it's 8.3ms.</p>
<p>The key optimisation insight: <strong>later stages are cheaper, and you can skip earlier ones.</strong></p>
<h2 id="which-properties-trigger-which-stages">Which properties trigger which stages</h2>
<table>
<thead>
<tr>
<th>You change…</th>
<th>Layout</th>
<th>Paint</th>
<th>Composite</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>width</code>, <code>height</code>, <code>top</code>, <code>left</code>, <code>margin</code>, <code>padding</code>, <code>font-size</code></td>
<td>✅</td>
<td>✅</td>
<td>✅</td>
</tr>
<tr>
<td><code>color</code>, <code>background-color</code>, <code>box-shadow</code>, <code>border-radius</code></td>
<td>—</td>
<td>✅</td>
<td>✅</td>
</tr>
<tr>
<td><code>transform</code>, <code>opacity</code> (on a composited layer)</td>
<td>—</td>
<td>—</td>
<td>✅</td>
</tr>
</tbody>
</table>
<p>Animating <code>left</code> from 0 to 300px re-runs layout and paint every frame. Animating <code>transform: translateX()</code> across the same distance only needs compositing — which can even run on the compositor thread while the main thread is busy.</p>
<pre><code class="hljs language-css"><span class="hljs-comment">/* ❌ Layout + paint every frame */</span>
<span class="hljs-selector-class">.drawer</span> { <span class="hljs-attribute">transition</span>: left <span class="hljs-number">300ms</span> ease; }
<span class="hljs-selector-class">.drawer</span><span class="hljs-selector-class">.open</span> { <span class="hljs-attribute">left</span>: <span class="hljs-number">0</span>; }

<span class="hljs-comment">/* ✅ Composite only */</span>
<span class="hljs-selector-class">.drawer</span> { <span class="hljs-attribute">transition</span>: transform <span class="hljs-number">300ms</span> ease; <span class="hljs-attribute">transform</span>: <span class="hljs-built_in">translateX</span>(-<span class="hljs-number">100%</span>); }
<span class="hljs-selector-class">.drawer</span><span class="hljs-selector-class">.open</span> { <span class="hljs-attribute">transform</span>: <span class="hljs-built_in">translateX</span>(<span class="hljs-number">0</span>); }
</code></pre>
<h2 id="layers-and-will-change">Layers and <code>will-change</code></h2>
<p>To composite an element on its own, the browser must promote it to a <strong>layer</strong>. Elements with active transform/opacity animations get promoted automatically, but promotion at animation start can cause a one-frame hitch. <code>will-change</code> tells the browser ahead of time:</p>
<pre><code class="hljs language-css"><span class="hljs-selector-class">.card</span><span class="hljs-selector-pseudo">:hover</span> { <span class="hljs-attribute">will-change</span>: transform; }
</code></pre>
<p>Use it sparingly:</p>
<ul>
<li>Every layer costs GPU memory. Putting <code>will-change: transform</code> on hundreds of list items can make performance <em>worse</em>, especially on mobile.</li>
<li>Prefer adding it just before an animation (on hover, or from JS right before starting) and removing it afterwards.</li>
<li>Layer promotion changes stacking and can affect text anti-aliasing.</li>
</ul>
<h2 id="forced-synchronous-layout-layout-thrashing">Forced synchronous layout (layout thrashing)</h2>
<p>Browsers batch style and layout work until the end of the frame. But if you <strong>read</strong> a layout property (<code>offsetHeight</code>, <code>getBoundingClientRect()</code>, <code>scrollTop</code>…) after <strong>writing</strong> a style, the browser must calculate layout immediately to give you a correct answer.</p>
<pre><code class="hljs language-js"><span class="hljs-comment">// ❌ Each iteration: write → read → forced layout</span>
items.<span class="hljs-title function_">forEach</span>(<span class="hljs-function">(<span class="hljs-params">item</span>) =></span> {
  item.<span class="hljs-property">style</span>.<span class="hljs-property">width</span> = container.<span class="hljs-property">offsetWidth</span> / <span class="hljs-number">3</span> + <span class="hljs-string">"px"</span>;
});

<span class="hljs-comment">// ✅ Read once, then write</span>
<span class="hljs-keyword">const</span> width = container.<span class="hljs-property">offsetWidth</span> / <span class="hljs-number">3</span>;
items.<span class="hljs-title function_">forEach</span>(<span class="hljs-function">(<span class="hljs-params">item</span>) =></span> {
  item.<span class="hljs-property">style</span>.<span class="hljs-property">width</span> = width + <span class="hljs-string">"px"</span>;
});
</code></pre>
<p>DevTools' Performance panel flags these as purple <strong>Layout</strong> blocks with a "Forced reflow" warning, pointing to the line that caused them.</p>
<h2 id="the-flip-technique">The FLIP technique</h2>
<p>Some animations seem to require animating layout — reordering a list, expanding a card into a modal. <strong>FLIP</strong> (First, Last, Invert, Play) turns them into cheap transforms:</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">function</span> <span class="hljs-title function_">flip</span>(<span class="hljs-params">element, mutate</span>) {
  <span class="hljs-comment">// First: record the starting position</span>
  <span class="hljs-keyword">const</span> first = element.<span class="hljs-title function_">getBoundingClientRect</span>();

  <span class="hljs-comment">// Apply the DOM/layout change instantly</span>
  <span class="hljs-title function_">mutate</span>();

  <span class="hljs-comment">// Last: record the final position</span>
  <span class="hljs-keyword">const</span> last = element.<span class="hljs-title function_">getBoundingClientRect</span>();

  <span class="hljs-comment">// Invert: move it back to where it started using a transform</span>
  <span class="hljs-keyword">const</span> dx = first.<span class="hljs-property">left</span> - last.<span class="hljs-property">left</span>;
  <span class="hljs-keyword">const</span> dy = first.<span class="hljs-property">top</span> - last.<span class="hljs-property">top</span>;
  <span class="hljs-keyword">const</span> sx = first.<span class="hljs-property">width</span> / last.<span class="hljs-property">width</span>;
  <span class="hljs-keyword">const</span> sy = first.<span class="hljs-property">height</span> / last.<span class="hljs-property">height</span>;

  <span class="hljs-comment">// Play: animate the transform back to identity</span>
  element.<span class="hljs-title function_">animate</span>(
    [
      { <span class="hljs-attr">transformOrigin</span>: <span class="hljs-string">"top left"</span>, <span class="hljs-attr">transform</span>: <span class="hljs-string">`translate(<span class="hljs-subst">${dx}</span>px, <span class="hljs-subst">${dy}</span>px) scale(<span class="hljs-subst">${sx}</span>, <span class="hljs-subst">${sy}</span>)`</span> },
      { <span class="hljs-attr">transformOrigin</span>: <span class="hljs-string">"top left"</span>, <span class="hljs-attr">transform</span>: <span class="hljs-string">"none"</span> },
    ],
    { <span class="hljs-attr">duration</span>: <span class="hljs-number">400</span>, <span class="hljs-attr">easing</span>: <span class="hljs-string">"cubic-bezier(0.16, 1, 0.3, 1)"</span> }
  );
}
</code></pre>
<p>The expensive layout happens once, and the animation itself is composite-only. This is exactly what Framer Motion's <code>layout</code> prop does under the hood.</p>
<h2 id="the-view-transitions-api">The View Transitions API</h2>
<p>For transitions between whole UI states — or even between pages — the browser can now do the FLIP work for you:</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">function</span> <span class="hljs-title function_">updateView</span>(<span class="hljs-params">render</span>) {
  <span class="hljs-keyword">if</span> (!<span class="hljs-variable language_">document</span>.<span class="hljs-property">startViewTransition</span>) <span class="hljs-keyword">return</span> <span class="hljs-title function_">render</span>();
  <span class="hljs-variable language_">document</span>.<span class="hljs-title function_">startViewTransition</span>(<span class="hljs-function">() =></span> <span class="hljs-title function_">render</span>());
}
</code></pre>
<pre><code class="hljs language-css"><span class="hljs-comment">/* Give elements a shared identity across the two states */</span>
<span class="hljs-selector-class">.product-thumb</span> { <span class="hljs-attribute">view-transition-name</span>: product-hero; }

<span class="hljs-comment">/* Customise the default cross-fade */</span>
::<span class="hljs-built_in">view-transition-old</span>(root),
::<span class="hljs-built_in">view-transition-new</span>(root) {
  <span class="hljs-attribute">animation-duration</span>: <span class="hljs-number">250ms</span>;
}
</code></pre>
<p>The browser snapshots the old state, runs your update, snapshots the new state and animates between them with pseudo-elements. Elements that share a <code>view-transition-name</code> morph from one position and size to the other. Cross-document view transitions (for multi-page apps) are enabled with a CSS opt-in: <code>@view-transition { navigation: auto; }</code>.</p>
<h2 id="paint-cost-is-real-too">Paint cost is real too</h2>
<p>Even without layout, some paints are expensive:</p>
<ul>
<li>Large <code>box-shadow</code> and <code>filter: blur()</code> values, especially when animated.</li>
<li><code>backdrop-filter</code> over large or frequently changing areas.</li>
<li>Huge areas invalidated by small changes. Use DevTools → Rendering → <strong>Paint flashing</strong> to see what repaints.</li>
</ul>
<p>A useful trick for animated shadows: put the shadow on a pseudo-element and animate its <code>opacity</code> instead of the shadow itself.</p>
<pre><code class="hljs language-css"><span class="hljs-selector-class">.card</span> { <span class="hljs-attribute">position</span>: relative; }
<span class="hljs-selector-class">.card</span><span class="hljs-selector-pseudo">::after</span> {
  <span class="hljs-attribute">content</span>: <span class="hljs-string">""</span>;
  <span class="hljs-attribute">position</span>: absolute;
  <span class="hljs-attribute">inset</span>: <span class="hljs-number">0</span>;
  <span class="hljs-attribute">border-radius</span>: inherit;
  <span class="hljs-attribute">box-shadow</span>: <span class="hljs-number">0</span> <span class="hljs-number">20px</span> <span class="hljs-number">40px</span> <span class="hljs-built_in">rgb</span>(<span class="hljs-number">0</span> <span class="hljs-number">0</span> <span class="hljs-number">0</span> / <span class="hljs-number">0.2</span>);
  <span class="hljs-attribute">opacity</span>: <span class="hljs-number">0</span>;
  <span class="hljs-attribute">transition</span>: opacity <span class="hljs-number">200ms</span>;
}
<span class="hljs-selector-class">.card</span><span class="hljs-selector-pseudo">:hover</span><span class="hljs-selector-pseudo">::after</span> { <span class="hljs-attribute">opacity</span>: <span class="hljs-number">1</span>; }
</code></pre>
<h2 id="containment">Containment</h2>
<p>The <code>contain</code> property tells the browser an element's internals don't affect the outside, so it can limit how far style, layout and paint work spreads:</p>
<pre><code class="hljs language-css"><span class="hljs-selector-class">.widget</span> { <span class="hljs-attribute">contain</span>: layout paint; }
<span class="hljs-selector-class">.offscreen-section</span> { <span class="hljs-attribute">content-visibility</span>: auto; <span class="hljs-attribute">contain-intrinsic-size</span>: auto <span class="hljs-number">600px</span>; }
</code></pre>
<p><code>content-visibility: auto</code> skips rendering off-screen subtrees entirely — often the biggest single win on long pages.</p>
<h2 id="respect-user-preferences">Respect user preferences</h2>
<p>Smooth isn't the same as necessary. Users with vestibular disorders can be made physically unwell by large motion:</p>
<pre><code class="hljs language-css"><span class="hljs-keyword">@media</span> (<span class="hljs-attribute">prefers-reduced-motion</span>: reduce) {
  *, *<span class="hljs-selector-pseudo">::before</span>, *<span class="hljs-selector-pseudo">::after</span> {
    <span class="hljs-attribute">animation-duration</span>: <span class="hljs-number">0.01ms</span> <span class="hljs-meta">!important</span>;
    <span class="hljs-attribute">transition-duration</span>: <span class="hljs-number">0.01ms</span> <span class="hljs-meta">!important</span>;
  }
}
</code></pre>
<h2 id="conclusion">Conclusion</h2>
<p>Animate <code>transform</code> and <code>opacity</code>, batch layout reads before writes, use FLIP or View Transitions when layout really must change, and keep layers and expensive paints under control. Once you know which pipeline stages each change triggers, hitting 60fps (or 120fps) becomes a design decision rather than
