3:T4227,<h2 id="what-a-proxy-actually-is">What a Proxy actually is</h2>
<p>A <code>Proxy</code> wraps a <strong>target</strong> object and lets you intercept the internal operations the engine performs on it — <code>[[Get]]</code>, <code>[[Set]]</code>, <code>[[HasProperty]]</code>, <code>[[Delete]]</code>, <code>[[OwnPropertyKeys]]</code>, <code>[[Call]]</code> and more. Each interceptable operation is a <strong>trap</strong> on the handler object.</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">const</span> target = { <span class="hljs-attr">greeting</span>: <span class="hljs-string">"hello"</span> };

<span class="hljs-keyword">const</span> proxy = <span class="hljs-keyword">new</span> <span class="hljs-title class_">Proxy</span>(target, {
  <span class="hljs-title function_">get</span>(<span class="hljs-params">target, key, receiver</span>) {
    <span class="hljs-variable language_">console</span>.<span class="hljs-title function_">log</span>(<span class="hljs-string">`read <span class="hljs-subst">${<span class="hljs-built_in">String</span>(key)}</span>`</span>);
    <span class="hljs-keyword">return</span> <span class="hljs-title class_">Reflect</span>.<span class="hljs-title function_">get</span>(target, key, receiver);
  },
});

proxy.<span class="hljs-property">greeting</span>; <span class="hljs-comment">// logs "read greeting", returns "hello"</span>
</code></pre>
<p>That's the whole API surface. The interesting part is using it correctly.</p>
<h2 id="why-you-should-always-forward-with-reflect">Why you should always forward with <code>Reflect</code></h2>
<p><code>Reflect</code> has one method per trap with the exact same signature. It performs the <em>default</em> behaviour. Using it instead of <code>target[key]</code> matters because of the <code>receiver</code> argument:</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">const</span> base = {
  <span class="hljs-attr">_name</span>: <span class="hljs-string">"base"</span>,
  <span class="hljs-keyword">get</span> <span class="hljs-title function_">name</span>() {
    <span class="hljs-keyword">return</span> <span class="hljs-variable language_">this</span>.<span class="hljs-property">_name</span>;
  },
};

<span class="hljs-keyword">const</span> proxy = <span class="hljs-keyword">new</span> <span class="hljs-title class_">Proxy</span>(base, {
  <span class="hljs-title function_">get</span>(<span class="hljs-params">target, key, receiver</span>) {
    <span class="hljs-keyword">return</span> target[key]; <span class="hljs-comment">// ❌ the getter runs with this === target</span>
  },
});

<span class="hljs-keyword">const</span> child = <span class="hljs-title class_">Object</span>.<span class="hljs-title function_">create</span>(proxy);
child.<span class="hljs-property">_name</span> = <span class="hljs-string">"child"</span>;
child.<span class="hljs-property">name</span>; <span class="hljs-comment">// "base" — wrong!</span>
</code></pre>
<p>When <code>child.name</code> walks up the prototype chain into the proxy, <code>receiver</code> is <code>child</code>. <code>target[key]</code> drops it and calls the getter on <code>target</code>. <code>Reflect.get(target, key, receiver)</code> preserves <code>this === child</code> and returns <code>"child"</code>. The same applies to <code>set</code> and setters.</p>
<h2 id="trap-invariants-what-you-cannot-lie-about">Trap invariants: what you cannot lie about</h2>
<p>Proxies can't violate certain invariants of the target, or the engine throws a <code>TypeError</code>. For example:</p>
<ul>
<li><code>get</code> must return the actual value for a <strong>non-writable, non-configurable</strong> data property.</li>
<li><code>has</code> can't hide a non-configurable property.</li>
<li><code>ownKeys</code> must include all non-configurable own keys, and must not add keys if the target is non-extensible.</li>
</ul>
<pre><code class="hljs language-js"><span class="hljs-keyword">const</span> frozen = <span class="hljs-title class_">Object</span>.<span class="hljs-title function_">freeze</span>({ <span class="hljs-attr">x</span>: <span class="hljs-number">1</span> });
<span class="hljs-keyword">const</span> liar = <span class="hljs-keyword">new</span> <span class="hljs-title class_">Proxy</span>(frozen, { <span class="hljs-attr">get</span>: <span class="hljs-function">() =></span> <span class="hljs-number">42</span> });
liar.<span class="hljs-property">x</span>; <span class="hljs-comment">// TypeError: 'get' on proxy: property 'x' is a read-only and</span>
        <span class="hljs-comment">// non-configurable data property ... but the proxy did not return its actual value</span>
</code></pre>
<p>These invariants exist so that security guarantees like <code>Object.freeze</code> can't be undermined by a proxy.</p>
<h2 id="example-1-negative-array-indices">Example 1: negative array indices</h2>
<pre><code class="hljs language-js"><span class="hljs-keyword">function</span> <span class="hljs-title function_">withNegativeIndices</span>(<span class="hljs-params">array</span>) {
  <span class="hljs-keyword">return</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">Proxy</span>(array, {
    <span class="hljs-title function_">get</span>(<span class="hljs-params">target, key, receiver</span>) {
      <span class="hljs-keyword">if</span> (<span class="hljs-keyword">typeof</span> key === <span class="hljs-string">"string"</span> &#x26;&#x26; <span class="hljs-regexp">/^-\d+$/</span>.<span class="hljs-title function_">test</span>(key)) {
        key = <span class="hljs-title class_">String</span>(target.<span class="hljs-property">length</span> + <span class="hljs-title class_">Number</span>(key));
      }
      <span class="hljs-keyword">return</span> <span class="hljs-title class_">Reflect</span>.<span class="hljs-title function_">get</span>(target, key, receiver);
    },
  });
}

<span class="hljs-keyword">const</span> list = <span class="hljs-title function_">withNegativeIndices</span>([<span class="hljs-string">"a"</span>, <span class="hljs-string">"b"</span>, <span class="hljs-string">"c"</span>]);
list[-<span class="hljs-number">1</span>]; <span class="hljs-comment">// "c"</span>
list.<span class="hljs-title function_">at</span>(-<span class="hljs-number">2</span>); <span class="hljs-comment">// "b" — all normal methods still work</span>
</code></pre>
<p>Note that property keys always arrive as <strong>strings or symbols</strong>, never numbers — <code>list[-1]</code> reaches the trap as <code>"-1"</code>.</p>
<h2 id="example-2-a-validation-layer">Example 2: a validation layer</h2>
<pre><code class="hljs language-js"><span class="hljs-keyword">function</span> <span class="hljs-title function_">typed</span>(<span class="hljs-params">schema</span>) {
  <span class="hljs-keyword">return</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">Proxy</span>({}, {
    <span class="hljs-title function_">set</span>(<span class="hljs-params">target, key, value, receiver</span>) {
      <span class="hljs-keyword">const</span> expected = schema[key];
      <span class="hljs-keyword">if</span> (!expected) {
        <span class="hljs-keyword">throw</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">TypeError</span>(<span class="hljs-string">`Unknown field "<span class="hljs-subst">${<span class="hljs-built_in">String</span>(key)}</span>"`</span>);
      }
      <span class="hljs-keyword">if</span> (<span class="hljs-keyword">typeof</span> value !== expected) {
        <span class="hljs-keyword">throw</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">TypeError</span>(<span class="hljs-string">`"<span class="hljs-subst">${<span class="hljs-built_in">String</span>(key)}</span>" must be <span class="hljs-subst">${expected}</span>, got <span class="hljs-subst">${<span class="hljs-keyword">typeof</span> value}</span>`</span>);
      }
      <span class="hljs-keyword">return</span> <span class="hljs-title class_">Reflect</span>.<span class="hljs-title function_">set</span>(target, key, value, receiver);
    },
  });
}

<span class="hljs-keyword">const</span> user = <span class="hljs-title function_">typed</span>({ <span class="hljs-attr">name</span>: <span class="hljs-string">"string"</span>, <span class="hljs-attr">age</span>: <span class="hljs-string">"number"</span> });
user.<span class="hljs-property">name</span> = <span class="hljs-string">"Ada"</span>;
user.<span class="hljs-property">age</span> = <span class="hljs-string">"36"</span>; <span class="hljs-comment">// TypeError: "age" must be number, got string</span>
</code></pre>
<p>The <code>set</code> trap must return <code>true</code> on success. Returning <code>false</code> throws a <code>TypeError</code> in strict mode — which is what modules and classes always are.</p>
<h2 id="example-3-a-tiny-reactive-store-how-vue-3-works">Example 3: a tiny reactive store (how Vue 3 works)</h2>
<p>Vue 3's reactivity is built on proxies. Here's the core idea in a few lines:</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">const</span> targetMap = <span class="hljs-keyword">new</span> <span class="hljs-title class_">WeakMap</span>(); <span class="hljs-comment">// target -> key -> Set&#x3C;effect></span>
<span class="hljs-keyword">let</span> activeEffect = <span class="hljs-literal">null</span>;

<span class="hljs-keyword">function</span> <span class="hljs-title function_">track</span>(<span class="hljs-params">target, key</span>) {
  <span class="hljs-keyword">if</span> (!activeEffect) <span class="hljs-keyword">return</span>;
  <span class="hljs-keyword">let</span> deps = targetMap.<span class="hljs-title function_">get</span>(target);
  <span class="hljs-keyword">if</span> (!deps) targetMap.<span class="hljs-title function_">set</span>(target, (deps = <span class="hljs-keyword">new</span> <span class="hljs-title class_">Map</span>()));
  <span class="hljs-keyword">let</span> set = deps.<span class="hljs-title function_">get</span>(key);
  <span class="hljs-keyword">if</span> (!set) deps.<span class="hljs-title function_">set</span>(key, (set = <span class="hljs-keyword">new</span> <span class="hljs-title class_">Set</span>()));
  set.<span class="hljs-title function_">add</span>(activeEffect);
}

<span class="hljs-keyword">function</span> <span class="hljs-title function_">trigger</span>(<span class="hljs-params">target, key</span>) {
  targetMap.<span class="hljs-title function_">get</span>(target)?.<span class="hljs-title function_">get</span>(key)?.<span class="hljs-title function_">forEach</span>(<span class="hljs-function">(<span class="hljs-params">fn</span>) =></span> <span class="hljs-title function_">fn</span>());
}

<span class="hljs-keyword">export</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">reactive</span>(<span class="hljs-params">obj</span>) {
  <span class="hljs-keyword">return</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">Proxy</span>(obj, {
    <span class="hljs-title function_">get</span>(<span class="hljs-params">target, key, receiver</span>) {
      <span class="hljs-title function_">track</span>(target, key);
      <span class="hljs-keyword">const</span> value = <span class="hljs-title class_">Reflect</span>.<span class="hljs-title function_">get</span>(target, key, receiver);
      <span class="hljs-comment">// Lazily make nested objects reactive</span>
      <span class="hljs-keyword">return</span> value !== <span class="hljs-literal">null</span> &#x26;&#x26; <span class="hljs-keyword">typeof</span> value === <span class="hljs-string">"object"</span> ? <span class="hljs-title function_">reactive</span>(value) : value;
    },
    <span class="hljs-title function_">set</span>(<span class="hljs-params">target, key, value, receiver</span>) {
      <span class="hljs-keyword">const</span> old = target[key];
      <span class="hljs-keyword">const</span> ok = <span class="hljs-title class_">Reflect</span>.<span class="hljs-title function_">set</span>(target, key, value, receiver);

      <span class="hljs-keyword">return</span> ok;

  });

    activeEffect = run;
    <span class="hljs-keyword">try</span> { <span class="hljs-title function_">fn</span>(); } <span class="hljs-keyword">finally</span> { activeEffect = <span class="hljs-literal">null</span>; }

  <span class="hljs-title function_">run</span>();

</code></pre>
<pre><code class="hljs language-js"><span class="hljs-keyword">const</span> state = <span class="hljs-title function_">reactive</span>({ <span class="hljs-attr">user</span>: { <span class="hljs-attr">name</span>: <span class="hljs-string">"Ada"</span> } });
<span class="hljs-title function_">watchEffect</span>(<span class="hljs-function">() =></span> <span class="hljs-variable language_">console</span>.<span class="hljs-title function_">log</span>(state.<span class="hljs-property">user</span>.<span class="hljs-property">name</span>));

<p>Using a <code>WeakMap</code> keyed by the raw target means dependency data is garbage-collected with the object. A production version also caches proxies per target (so <code>reactive(obj) === reactive(obj)</code>), and handles arrays, <code>Map</code>/<code>Set</code>, and <code>has</code>/<code>ownKeys</code> traps for <code>in</code> and iteration.</p>
<h2 id="revocable-proxies-for-capability-security">Revocable proxies for capability security</h2>
<p><code>Proxy.revocable</code> returns a proxy plus a <code>revoke</code> function. After revoking, <em>every</em> operation on the proxy throws. That's useful for handing a third-party plugin temporary access:</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">const</span> { <span class="hljs-attr">proxy</span>: api, revoke } = <span class="hljs-title class_">Proxy</span>.<span class="hljs-title function_">revocable</span>(internalApi, {});
plugin.<span class="hljs-title function_">init</span>(api);
<span class="hljs-comment">// later...</span>
<span class="hljs-title function_">revoke</span>(); <span class="hljs-comment">// the plugin can no longer touch internalApi through `api`</span>
</code></pre>
<h2 id="performance-and-pitfalls">Performance and pitfalls</h2>
<ul>
<li><strong>Proxies are slower</strong> than plain property access because traps defeat many engine optimisations (inline caches). Don't put them in hot inner loops.</li>
<li><strong>Identity:</strong> <code>proxy !== target</code>. Code that uses objects as <code>Map</code> keys or does <code>===</code> checks can break.</li>
<li><strong>Private fields don't work through proxies.</strong> <code>#field</code> access checks the <em>actual</em> object, and the proxy isn't the instance:</li>
</ul>
<pre><code class="hljs language-js"><span class="hljs-keyword">class</span> <span class="hljs-title class_">Counter</span> {
  #count = <span class="hljs-number">0</span>;
  <span class="hljs-title function_">inc</span>(<span class="hljs-params"></span>) { <span class="hljs-keyword">return</span> ++<span class="hljs-variable language_">this</span>.#count; }
}
<span class="hljs-keyword">const</span> p = <span class="hljs-keyword">new</span> <span class="hljs-title class_">Proxy</span>(<span class="hljs-keyword">new</span> <span class="hljs-title class_">Counter</span>(), {});
p.<span class="hljs-title function_">inc</span>(); <span class="hljs-comment">// TypeError: Cannot read private member #count</span>
</code></pre>
<p>Fix it by binding methods to the target in the <code>get</code> trap when the value is a function.</p>
<ul>
<li><strong>Built-ins with internal slots</strong> (<code>Map</code>, <code>Set</code>, <code>Date</code>, typed arrays) have the same problem — their methods need <code>this</code> to be the real object.</li>
</ul>
<h2 id="conclusion">Conclusion</h2>
<p>Use <code>Reflect</code> to forward every trap with its receiver, respect the invariants, and keep proxies out of hot paths.
