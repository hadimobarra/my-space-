3:T329a,<h2 id="what-inp-measures">What INP measures</h2>
<p><strong>Interaction to Next Paint</strong> observes every click, tap and key press during a page visit and reports (roughly) the <em>worst</em> one — the 98th percentile for pages with many interactions. Each interaction's latency is the time from the input until the browser <strong>paints the next frame</strong> after handling it.</p>
<p>That latency has three parts:</p>
<ol>
<li><strong>Input delay</strong> — the main thread was busy with something else when the user interacted.</li>
<li><strong>Processing time</strong> — your event handlers ran.</li>
<li><strong>Presentation delay</strong> — style, layout, paint and compositing for the resulting frame.</li>
</ol>
<p>Thresholds: <strong>≤ 200ms is good</strong>, <strong>> 500ms is poor</strong>, measured at the 75th percentile of page loads.</p>
<p>Because INP covers the whole visit and not just the first input, it punishes exactly the things heavy single-page apps do: big re-renders, synchronous state updates and long tasks during hydration.</p>
<h2 id="step-1-measure-in-the-field">Step 1: measure in the field</h2>
<p>Lab tools can't know which interactions real users perform. Collect field data with the <code>web-vitals</code> library and the attribution build:</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">import</span> { onINP } <span class="hljs-keyword">from</span> <span class="hljs-string">"web-vitals/attribution"</span>;

<h2 id="step-2-do-the-visible-work-first-defer-the-rest">Step 2: do the visible work first, defer the rest</h2>
<p>The single most effective pattern: in the handler, do only what's needed for the <strong>next frame</strong>, then yield before the rest.</p>
<pre><code class="hljs language-js"><span class="hljs-comment">// Yield with a *task*, so the browser can paint and handle input</span>
<span class="hljs-keyword">function</span> <span class="hljs-title function_">yieldToMain</span>(<span class="hljs-params"></span>) {
  <span class="hljs-keyword">if</span> (globalThis.<span class="hljs-property">scheduler</span>?.<span class="hljs-property">yield</span>) <span class="hljs-keyword">return</span> scheduler.<span class="hljs-title function_">yield</span>();
  <span class="hljs-keyword">return</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">Promise</span>(<span class="hljs-function">(<span class="hljs-params">resolve</span>) =></span> <span class="hljs-built_in">setTimeout</span>(resolve, <span class="hljs-number">0</span>));
}

button.<span class="hljs-title function_">addEventListener</span>(<span class="hljs-string">"click"</span>, <span class="hljs-title function_">async</span> () => {
  <span class="hljs-comment">// 1. Immediate visual feedback</span>
  button.<span class="hljs-property">classList</span>.<span class="hljs-title function_">add</span>(<span class="hljs-string">"is-loading"</span>);

  <span class="hljs-comment">// 2. Let the browser paint that feedback</span>
  <span class="hljs-keyword">await</span> <span class="hljs-title function_">yieldToMain</span>();

  <span class="hljs-comment">// 3. Non-urgent work happens after the paint</span>
  <span class="hljs-title function_">recalculateRecommendations</span>();
  <span class="hljs-title function_">sendAnalytics</span>(<span class="hljs-string">"click"</span>);

</code></pre>
<p>Analytics, logging and prefetching almost never need to block the frame. Move them behind a yield or into <code>requestIdleCallback</code>.</p>
<h2 id="step-3-break-up-long-tasks">Step 3: break up long tasks</h2>
<p>Any task over 50ms is a <strong>long task</strong>. If one is running when the user clicks, the click has to wait. Chunk heavy loops:</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">async</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">filterLargeList</span>(<span class="hljs-params">items, predicate</span>) {
  <span class="hljs-keyword">const</span> result = [];
  <span class="hljs-keyword">let</span> deadline = performance.<span class="hljs-title function_">now</span>() + <span class="hljs-number">8</span>; <span class="hljs-comment">// ~half a frame</span>
  <span class="hljs-keyword">for</span> (<span class="hljs-keyword">let</span> i = <span class="hljs-number">0</span>; i &#x3C; items.<span class="hljs-property">length</span>; i++) {
    <span class="hljs-keyword">if</span> (<span class="hljs-title function_">predicate</span>(items[i])) result.<span class="hljs-title function_">push</span>(items[i]);
    <span class="hljs-keyword">if</span> (performance.<span class="hljs-title function_">now</span>() > deadline) {
      <span class="hljs-keyword">await</span> <span class="hljs-title function_">yieldToMain</span>();
      deadline = performance.<span class="hljs-title function_">now</span>() + <span class="hljs-number">8</span>;
    }
  }
  <span class="hljs-keyword">return</span> result;
}
</code></pre>
<p>If the work is pure computation (parsing, sorting, diffing), move it <strong>off the main thread</strong> entirely into a Web Worker.</p>
<h2 id="step-4-react-specific-techniques">Step 4: React-specific techniques</h2>
<p>React 18+ gives you concurrent rendering that can be interrupted by input:</p>
<pre><code class="hljs language-jsx"><span class="hljs-keyword">import</span> { useState, useTransition, useDeferredValue } <span class="hljs-keyword">from</span> <span class="hljs-string">"react"</span>;

<span class="hljs-keyword">function</span> <span class="hljs-title function_">Search</span>(<span class="hljs-params">{ items }</span>) {
  <span class="hljs-keyword">const</span> [query, setQuery] = <span class="hljs-title function_">useState</span>(<span class="hljs-string">""</span>);
  <span class="hljs-keyword">const</span> [isPending, startTransition] = <span class="hljs-title function_">useTransition</span>();
  <span class="hljs-keyword">const</span> [filter, setFilter] = <span class="hljs-title function_">useState</span>(<span class="hljs-string">""</span>);

  <span class="hljs-keyword">return</span> (
    <span class="xml"><span class="hljs-tag">&#x3C;></span>
      <span class="hljs-tag">&#x3C;<span class="hljs-name">input</span>
        <span class="hljs-attr">value</span>=<span class="hljs-string">{query}</span>
        <span class="hljs-attr">onChange</span>=<span class="hljs-string">{(e)</span> =></span> {
          setQuery(e.target.value);                       // urgent: keep typing snappy
          startTransition(() => setFilter(e.target.value)); // can be interrupted
        }}
      />
      {isPending &#x26;&#x26; <span class="hljs-tag">&#x3C;<span class="hljs-name">Spinner</span> /></span>}
      <span class="hljs-tag">&#x3C;<span class="hljs-name">Results</span> <span class="hljs-attr">items</span>=<span class="hljs-string">{items}</span> <span class="hljs-attr">filter</span>=<span class="hljs-string">{filter}</span> /></span>
    <span class="hljs-tag">&#x3C;/></span></span>
  );
}
</code></pre>
<p>The input update commits immediately; the expensive results render happens in a transition that React abandons and restarts if another keystroke arrives. <code>useDeferredValue</code> achieves the same thing when you don't control the state setter.</p>
<p>Other React wins:</p>
<ul>
<li><strong>Memoise expensive subtrees</strong> (<code>memo</code>, or the React Compiler) so a keystroke doesn't re-render the world.</li>
<li><strong>Virtualise long lists</strong> — rendering 5,000 rows is slow no matter how fast each row is.</li>
<li><strong>Avoid hydration-time long tasks</strong> with selective hydration (<code>Suspense</code> boundaries) and by shipping less client JavaScript (Server Components).</li>
</ul>
<h2 id="step-5-reduce-presentation-delay">Step 5: reduce presentation delay</h2>
<p>Even with a fast handler, the frame can be slow to produce:</p>
<ul>
<li><strong>Large DOMs</strong> make style recalculation and layout expensive. Keep it under a few thousand nodes where possible.</li>
<li><strong><code>content-visibility: auto</code></strong> lets the browser skip rendering off-screen sections:</li>
</ul>
<pre><code class="hljs language-css"><span class="hljs-selector-class">.feed-item</span> {
  <span class="hljs-attribute">content-visibility</span>: auto;
  <span class="hljs-attribute">contain-intrinsic-size</span>: auto <span class="hljs-number">320px</span>; <span class="hljs-comment">/* placeholder size to avoid scroll jumps */</span>
}
</code></pre>
<ul>
<li><strong>Avoid layout thrashing</strong> — interleaving DOM writes and layout reads in a loop forces synchronous layout each iteration:</li>
</ul>
<pre><code class="hljs language-js"><span class="hljs-comment">// ❌ read → write → read → write: forced layout each time</span>
<span class="hljs-keyword">for</span> (<span class="hljs-keyword">const</span> el <span class="hljs-keyword">of</span> cards) el.<span class="hljs-property">style</span>.<span class="hljs-property">height</span> = el.<span class="hljs-property">offsetWidth</span> * <span class="hljs-number">0.5</span> + <span class="hljs-string">"px"</span>;

cards.<span class="hljs-title function_">forEach</span>(<span class="hljs-function">(<span class="hljs-params">el, i</span>) =></span> (el.<span class="hljs-property">style</span>.<span class="hljs-property">height</span> = widths[i] * <span class="hljs-number">0.5</span> + <span class="hljs-string">"px"</span>));
</code></pre>
<h2 id="a-debugging-workflow-that-works">A debugging workflow that works</h2>
<ol>
<li>Find the worst interactions from field data (target selector + phase breakdown).</li>
<li>Reproduce in Chrome DevTools' <strong>Performance</strong> panel with CPU throttling at 4× or 6×.</li>
<li>Look at the <strong>Interactions</strong> track; expand the long interaction and read the flame chart under it.</li>
<li>Apply the matching fix from the table above, then verify in the field — lab improvements don't always transfer.</li>
</ol>
<h2 id="conclusion">Conclusion</h2>
<p>INP rewards apps that respond first and compute later. Show feedback in the next frame, yield before non-urgent work, keep long tasks off the main thread, and let React's transitions keep input urgent.
