## The setup

This site is a Next.js 16 App Router project with `output: "export"`. The build produces plain files for GitHub Pages: no server, no edge functions, no image optimizer. It has two languages, a blog and a set of case studies.

```embed
export-pipeline
```

Static export is a great fit for content sites. These are the things that surprised me.

## 1. Metadata is replaced, not merged

A layout sets a default social image. A page sets its own title for sharing:

```ts title="app/blog/[slug]/page.tsx"
export async function generateMetadata() {
  return {
    openGraph: { title: "My article", type: "article" },
  };
}
```

The page now has *no* image. Next.js merges metadata shallowly: the page's `openGraph` object [replaces](https://nextjs.org/docs/app/api-reference/functions/generate-metadata#merging) the layout's. The same goes for `alternates`, so one article-specific canonical URL also removed the RSS link from every article here. Nothing warns you, and the page looks perfect until someone shares it.

The inverse hurts too. Pages that *don't* set `alternates` inherit it. The blog index was telling search engines that its canonical URL was the homepage.

The fix is one function that builds complete metadata, used by every page:

```ts title="lib/seo.ts"
export function pageMetadata({ locale, path, title, description, image }: Input): Metadata {
  const url = absoluteUrl(localePath(locale, path));
  return {
    title,
    description,
    alternates: { canonical: url, languages: alternatesFor(path), types: rssFor(locale) },
    openGraph: { title, description, url, images: [image] },
    twitter: { card: "summary_large_image", title, description, images: [image] },
  };
}
```

## 2. Two languages want two root layouts

`lang` and `dir` belong on `<html>`, and only a root layout renders it. Route groups allow several:

```text
app/
  (en)/layout.tsx        → <html lang="en" dir="ltr">
  (en)/blog/page.tsx     → /blog/
  (fa)/layout.tsx        → <html lang="fa" dir="rtl">
  (fa)/fa/blog/page.tsx  → /fa/blog/
```

Both layouts are five lines around a shared component. Two consequences to plan for:

- Navigating between them is a full page load, so use a plain `<a>` for the language switch.
- There is no single layout for the 404 page. You need `global-not-found.tsx`, which is [behind a flag](https://nextjs.org/docs/app/api-reference/file-conventions/not-found) in Next.js 16.

## 3. Don't use `opengraph-image.tsx` with static export

The file convention produces a file called `opengraph-image`, without an extension. A static host picks the content type from the extension, so it can't know it's a PNG. A route handler gives you control over the name:

```ts title="app/og/[kind]/[file]/route.tsx" {3}
export const dynamic = "force-static";

export const generateStaticParams = () => posts.map((p) => ({ kind: "blog", file: `${p.slug}.png` }));

export async function GET(_: Request, { params }: Context) {
  const { file } = await params;
  return new ImageResponse(<Card post={find(file)} />, { width: 1200, height: 630 });
}
```

## 4. Server components are paid for twice

A server component adds no JavaScript. Its output still travels twice: as HTML, and again inside the React payload that hydration needs.

For text that compresses well, it hardly matters. For inline SVG it does. About thirty brand icons pushed the homepage from 40 to 78 KB of compressed HTML. Moving them into one external sprite brought it back:

```tsx
<svg aria-hidden width={16} height={16}>
  <use href="/brand-icons.svg#react" />
</svg>
```

## 5. Pass server-rendered nodes into client components

The blog index filters cards in the browser. That doesn't mean the cards must be client components. The server renders them, and the client decides which to show:

```tsx {4}
<BlogFilter
  items={posts.map((post) => ({
    search: post.title.toLowerCase(),
    card: <PostCard post={post} />, // rendered on the server
  }))}
/>
```

More on this in [the mental model for server components](/blog/react-server-components-mental-model/).

## 6. Check what your bundler merges

I used `next/font` in both layouts, one font per language. The build merged their CSS into one chunk, and preloading works per chunk. Every English page preloaded the Persian fonts, and the other way around.

Nothing in the code looked wrong. The network panel showed it immediately. I ended up hosting the fonts myself, with an explicit preload per language. The [longer version](/blog/less-javascript-same-blocking-time/) includes the wrong fix I tried first.

## 7. Test the output, not the app

With static export, the `out` folder *is* the product. So test that: serve it the way the host does, and check files directly.

```ts title="tests/seo.spec.ts"
test("sitemap lists existing canonical URLs only", () => {
  const urls = [...xml.matchAll(/<loc>([^<]+)<\/loc>/g)].map(([, url]) => url);
  expect(urls.sort()).toEqual(htmlFiles.map((f) => `${SITE}${f.path}`).sort());
});
```

Similar tests check that every internal link and anchor resolves, that each page has an existing social image, and that language links point back at each other. They run in seconds and need no browser.

## What I would choose again

Static export, server components by default, a single metadata function, and tests on the output. The framework is good at this. The surprises all come from the same place: *conventions do something on your behalf, and you only see the result in the build.* Look at the build.
